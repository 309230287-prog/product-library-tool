# 问题陈述：五期 — 规则引擎 + DeepSeek 复核

## 问题

一期清洗的规则引擎在处理语义歧义时存在盲区，导致误判。典型错误：

| 组号 | 商品A | 商品B | 规则引擎判定 | 实际应该 |
|------|-------|-------|-------------|---------|
| 重103 | 黄骨鱼抄码-EE152717（斤/水产类） | 黄骨鱼（杀好）抄码-EE337905（斤/水产类） | 完全重复 | 不同商品（杀好 vs 未杀） |
| 重111 | 湖南腊肉抄码-CC353502（斤/干调类） | 湖南腊肉（二刀肉）抄码-CC2536839（斤/干调类） | 完全重复 | 不同商品（二刀肉是不同部位） |

规则引擎只能比对 (core, unit, category) 三元组，无法理解"杀好"、"二刀肉"等语义差异。纯规则方案在 12440 条中产生约 655 条标记，其中一部分是误判。

## 背景

- 一期已用规则引擎完成全量清洗（12440 条），结果已手动修正并写入 `商品库整理_结果.xlsx`
- 四期 Web 工具重新跑规则引擎，又跑出了相同的旧 bug
- 三期已实现 DeepSeek 判断模块（`scripts/judge.py`），有现成的 API 调用基础设施
- API 调用量约 300 次（按组分批，每组 1 次），成本完全可控

## 异常分类说明

规则引擎的异常分类共有 5 种，处理方式不同：

| 分类 | 含义 | 数量（约） | 是否送 DeepSeek | 原因 |
|------|------|-----------|----------------|------|
| 完全重复 | 规则认为两个或多个商品是同一个东西，只是重复编码 | 387 | **是** | 语义判断，需要理解"杀好""二刀肉"等差异 |
| 抄码名重复 | 规则认为抄码名和正常名是同一商品的两个编码形式 | 256 | **是** | 需要确认抄码名是否真的对应正常名 |
| 异名同物 | 规则认为名称不同但指同一商品 | 12 | **是** | 异名关系需要语义确认 |
| 缺省值 | 名称或描述字段含"缺省值"，数据不完整 | 229 | **否** | 不是"同与不同"的问题，是数据缺失问题 |
| 正常 | 经规则引擎确认无异常 | 11556 | **否** | 无需处理 |

## 处理流程

```
规则引擎跑完 → 收集标记为"完全重复/抄码名重复/异名同物"的行
                     ↓
            按组号分组（同组商品放在一起）
            组号如：重103、抄38、异2
                     ↓
        每组构造一个请求发给 DeepSeek
        请求内容：同组内每行的（名称、单位、描述、分类）
        不含 SPUID、组号、建议等无关信息
                     ↓
        DeepSeek 逐组判断：这些商品是同一个东西吗？
                     ↓
           ┌──────────┴──────────┐
           ↓                     ↓
       是（同一商品）           否（不同商品）
           ↓                     ↓
    保持原标记不变          整组所有行改回"正常"
    （完全重复/抄码名重复    （组号清除，异常分类=正常）
     异名同物保持不变）
```

### 关键细节

1. **按组判断，不是按行判断**：规则引擎已经把疑似重复的商品分到了同一组（组号如"重103"、"抄38"、"异2"）。以组为单位送 DeepSeek，每组只调用 1 次 API。
2. **一组全改或全不改**：DeepSeek 说"是同一组"→ 整组保持原标记；DeepSeek 说"不是同一组"→ 整组全部改回"正常"。不拆组、不单独改某一行。
3. **缺省值不受影响**：标记为"缺省值"的 229 行不参与复核，保持原样。
4. **DeepSeek 的输入**：同组内每行的（名称、单位、描述、分类），不含 SPUID、组号、建议等无关信息。
5. **DeepSeek 的输出**：只需要回答"是/否"，不需要理由。格式化为 JSON。
6. **API 调用量**：每组 1 次，约 300 组 = 约 300 次调用。

## 成功标准

- [ ] 重103（黄骨鱼抄码 vs 黄骨鱼（杀好）抄码）→ DeepSeek 判定为不同商品 → 两条都改回"正常"
- [ ] 重111（湖南腊肉抄码 vs 湖南腊肉（二刀肉）抄码）→ DeepSeek 判定为不同商品 → 两条都改回"正常"
- [ ] 真正重复的商品（如同一商品的抄码名 vs 正常名，如抄38）→ DeepSeek 判定为同一商品 → 保留"抄码名重复"
- [ ] 缺省值标记全部保留，不受复核影响
- [ ] 12440 条总数不变
- [ ] 总 API 调用量 < 500 次（每组 1 次）
