# 实施计划：商品库整理 v3

## 总流程

```
Excel读入 → 逐行翻译 → 建索引 → 逐级标重复 → 写入Excel + 输出报告
                ↑                        ↑
          SemanticTranslator       RuleEngine(5级+1待确认)
```

共4个阶段，每个阶段有明确的输入、输出、验证方式。

## 阶段1：数据读入 + 语义翻译

### 做什么

读入12440行，每行翻译成标准语义结构。

### 翻译器设计

```
SemanticTranslator
├── translate_name(raw_name, category) → NameMeaning
│   ├── core: str          # 核心商品名（去后缀、抄码、品牌、状态词）
│   ├── paren_content: str|None  # 括号内原文，不猜测不丢弃（新增）
│   ├── has_chaoma: bool   # 名称是否含抄码
│   ├── has_status: str    # 处理状态，无则为None
│   │                       # 来源①括号（仅状态词：杀好/鲜/活/冻/冰鲜/速冻/散装/散称）
│   │                       #     ②前缀（活/鲜/干/冰鲜/杀好/散装）
│   ├── status_from_prefix: bool  # 状态来自前缀(True)还是括号(False)
│   └── raw: str           # 保留原始名
│
├── translate_desc(raw_desc, unit) → DescMeaning
│   ├── has_spec: bool     # 是否写了规格(描述=单位→视同没写)
│   ├── spec_core: str     # 规格主语义（已翻译）
│   ├── is_quesheng: bool  # 描述是否含"缺省值"
│   ├── is_pure_text: bool # 描述是纯文字(非规格非抄码)→True
│   └── raw: str
│
├── translate_unit(raw_unit) → str  # 原样保留
│
├── are_categories_compatible(cat_a, cat_b) → bool
│
└── is_status_redundant(status, category) → bool
    # 鲜在鲜肉类、干在干调类、冰鲜在水产类→冗余
```

### 名称翻译的具体步骤

```
示例1：括号状态词
输入："草鱼（杀好）抄码-EE337860"
  ↓ 1. 砍后缀(-EE337860) + 末尾残留【
"草鱼（杀好）抄码"
  ↓ 2. 剥离"抄码"
"草鱼（杀好）"
  ↓ 3. 剥离品牌词（无匹配，跳过）
"草鱼（杀好）"
  ↓ 4. 提取括号处理状态："杀好" → has_status="杀好", status_from_prefix=False
  ↓ 5. 核心名：去掉处理状态括号后 → "草鱼"
  ↓ 输出
NameMeaning(core="草鱼", has_chaoma=True, has_status="杀好")

示例2：前缀状态词
输入："鲜牛腩抄码-DD268021"
  ↓ 1. 砍后缀(-DD268021)
"鲜牛腩抄码"
  ↓ 2. 剥离"抄码"
"鲜牛腩"
  ↓ 3. 剥离品牌词（无匹配，跳过）
"鲜牛腩"
  ↓ 4. 识别前缀状态词："鲜"在已知前缀表中 → has_status="鲜", status_from_prefix=True
  ↓ 5. 核心名：去掉前缀状态词 → "牛腩"
  ↓ 输出
NameMeaning(core="牛腩", has_chaoma=True, has_status="鲜", status_from_prefix=True)

示例3：前缀+括号双状态
输入："冰鲜红杉鱼（杀好）抄码-EE253551"
  ↓ 1. 砍后缀
"冰鲜红杉鱼（杀好）抄码"
  ↓ 2. 剥离"抄码"
"冰鲜红杉鱼（杀好）"
  ↓ 3-5. 前缀="冰鲜" + 括号="杀好" → has_status="冰鲜+杀好"
  ↓ 核心名="红杉鱼"
  ↓ 输出
NameMeaning(core="红杉鱼", has_chaoma=True, has_status="冰鲜+杀好")
```

### 描述翻译的具体步骤

```
示例1：复合描述
输入："7*17.5kg，实际抄码"
  ↓ 1. 判断描述=单位？ 7*17.5kg ≠ unit → is_desc_eq_unit=False
  ↓ 2. 判断是否无规格：不是空/抄码/散称/散装 → has_spec=True
  ↓ 3. 拆分逗号：["7*17.5kg", "实际抄码"]
  ↓ 4. 取第一段为规格主语义："7*17.5kg"
  ↓ 5. 统一乘号 → 去外围1* → 去品牌词（无）
  ↓ 输出
DescMeaning(has_spec=True, spec_core="7*17.5kg")

示例2：描述=单位
输入：desc="个", unit="个"
  ↓ 1. 判断描述=单位？是 → is_desc_eq_unit=True
  ↓ 2. 视为没写规格 → has_spec=False
  ↓ 输出
DescMeaning(has_spec=False, spec_core=None, is_desc_eq_unit=True)

示例3：纯文字
输入：desc="顺陶陶"
  ↓ 1. 判断描述=单位？否
  ↓ 2. 判断无规格？不是空/抄码/散称 → has_spec=True
  ↓ 3. 纯文字标记 → is_pure_text=True
  ↓ 4. spec_core="顺陶陶"（保留原文，无法比较）
  ↓ 输出
DescMeaning(has_spec=True, spec_core="顺陶陶", is_pure_text=True)
```

### 异常场景处理

翻译过程中可能遇到数据不完整或格式异常，不能直接崩。

| 异常场景 | 处理方式 | 理由 |
|----------|---------|------|
| 名称为空 | 跳过翻译，标记为"数据异常"，入待确认清单 | 没有名没办法判断 |
| 单位为空 | 原样保留，翻译结果unit=""，后续同名+空单位的仍能匹配 | 单位空可能是漏填，不阻断匹配 |
| 分类为空 | 视为独立分类，不参与互通匹配 | 空分类匹配不了任何分类 |
| 描述翻译失败 | 原样保留spec_core，不抛异常 | 未知格式不代表错误，只是我们不会翻译 |
| 名称去后缀后为空 | core保留为去后缀后的结果（可能空），不抛异常 | 极少见，宁可留空错标也比崩掉好 |
| 含未知品牌词 | 不影响翻译，不剥离 | 品牌表覆盖不全很正常 |
| 含未知处理状态 | 不影响翻译，不剥离 | 处理状态表覆盖不全很正常 |

## 阶段2：构建匹配索引

### 做什么

建三张索引表，供后续规则快速查找。

### 索引设计

| 索引 | Key | Value | 用途 |
|------|-----|-------|------|
| idx_name_unit | (core_name, unit) | [row...] | 完全重复查找 |
| idx_no_cm_unit | (core_name_no_cm, unit) | [row...] | 抄码名匹配 |
| idx_by_spuid | spuid | row | 按编码查行 |

- 索引只包含尚未被前面级别标记的行
- core_name_no_cm = core 再去掉抄码后的最简名

### 阶段2验证

- idx_name_unit 的 key 数量 + 重复组数量关系正确

## 阶段3：逐级标记（RuleEngine）

按优先级顺序执行，一行一旦被标记就锁定。

### 3.1 缺省值

```
FOR each row:
    IF row.category IS NOT None: SKIP
    IF "缺省值" in row.name_raw OR row.desc_meaning.is_quesheng:
        row.category = "缺省值"
        row.group_id = "缺省"
        row.group_desc = 含/不含区分说明
        row.suggestion = "补全信息或停用"
```

**验证**：标记数量 ≈ 229，名称含的44条 + 描述含的185条

### 3.2 完全重复

```
FOR each (core_name, unit) group in idx_name_unit WHERE size >= 2:
    FOR each cat group:
        FOR each pair (A, B) in cat group:
            # 状态检查
            IF A.has_status != B.has_status:
                # 前缀冗余：鲜在鲜肉类、干在干调类、冰鲜在水产类
                IF is_status_redundant(A) OR is_status_redundant(B):
                    # 一方有冗余前缀，另一方无 → 可标重
                    PASS
                ELSE:
                    SKIP  # 状态冲突，不标
            # 描述检查
            IF desc_equivalent(A.desc, B.desc):
                MARK both as "完全重复", group_id="重N"
            ELIF one has spec, one doesn't:
                ADD to 待确认清单
```

**status_redundant**：
```
IF status=="鲜" AND category in ("鲜肉类","鲜肉类（通用）"): return True
IF status=="干" AND category in ("干调类","干调类（通用）"): return True
IF status=="冰鲜" AND category in ("水产类","水产类（通用）","水产品"): return True
ELSE: return False
```

**验证**：约115-130组，抽查"三角龙骨"组、"一次性锡纸蛋挞托"组

### 3.3 抄码名重复

```
FOR each row A WHERE A.has_chaoma AND A.category IS None:
    no_cm = A.core_name_no_cm  # 去抄码后的核心名
    matches = idx_no_cm_unit[(no_cm, A.unit)]
    matches = [B for B in matches if NOT B.has_chaoma AND B.category IS None]
    IF matches not empty:
        B = first match with same/compatible category
        MARK A as "抄码名重复", group_id="抄N"
        MARK B as "抄码名重复", group_id="抄N" (if not already marked)
```

**验证**：约115条，"冬枣抄码"匹配到"冬枣"

### 3.4 异名同物

```
FOR each (name_a, name_b) in SYNONYM_MAP:
    rows_a = idx_no_cm_unit matching name_a
    rows_b = idx_no_cm_unit matching name_b
    FOR each pair (A, B) in cross join:
        IF A.unit == B.unit AND compatible_cat(A.cat, B.cat):
            IF both not marked AND both no status conflict:
                MARK both as "异名同物", group_id="异N"
```

**验证**：约80-150条，每个异名对都能在数据中找到对应行

### 3.5 正常

```
FOR each row WHERE category IS None:
    row.category = "正常"
```

### 3.6 待确认清单闭环

两种来源汇聚到sheet `待确认`：
- 分类冲突：名称+单位相同，分类不互通
- 规格待确认：一个写了规格一个没写

**人工确认→合并流程**：

1. **待确认清单独立输出**为一个sheet（`待确认`），列：SPUID、名称、单位、描述、分类、冲突类型、对方SPUID、人工判定结果（空=待确认）
2. **人工只需填一列**："人工判定"列，选项：确认重复 / 不重复 / 保留判断
3. **合并回主表**：确认重复的行→异常分类改为"完全重复"，组号续编；不重复的→改为"正常"
4. **合并脚本独立**：`scripts/merge_review.py`，读取人工填好的sheet，合并回主xlsx

```
待确认清单(输出)  →  人工填"人工判定"列  →  merge_review.py 合并回主表
```

## 改规则重跑

需求迭代多轮是常态，不能每次都从零开始。设计好"改规则→重跑→看diff→确认"的流程：

1. **只改translator.py**：翻译规则全在这里，改翻译不改规则引擎
2. **输出带时间戳的副本**：每次重跑输出 `商品库整理_YYYYMMDD_HHMMSS.xlsx`，不覆盖上次结果
3. **diff对比**：`scripts/diff_runs.py`，传入两次的输出文件：
   - 新增标注的行（哪些行上一版未标、这一版标了）
   - 分类变化的行（异常分类被修改）
   - 行数不变确认
4. **验收案例自动校验**：脚本内置验收案例列表，跑完自动对比预期，不一致时标红

```
改translator.py  →  run.py重跑  →  diff_runs.py对比上次  →  确认改动符合预期
```

## 二期：增量防重复

一期做完全量清洗后，日常新品入库需要防重复。复用一期的翻译器和索引。

```
新品 → translator.translate(新品) → 在已有索引中查重 → 命中? → 告警"疑似与XXX重复"
                                               ↓未命中
                                               正常入库 → 更新索引
```

- 查重规则复用一期的完全重复 + 抄码名重复 + 异名同物
- 不自动拒绝，只提示，人工确认后入库
- 每次入库后增量更新索引
- 入口：`scripts/check_new.py`，接受新品SPU信息，返回查重结果
