#### B. 名称中提取规格

在 `translate_name` 中，品牌提取之前，扫描名称中的数字+单位模式：

```
识别模式（按优先级）：
  1. 复杂规格: \d+\.?\d*[*×xX]\d+\.?\d*[*×xX]?\d*\.?\d*[^\s]*  → "1*4*2.5kg", "1*2.5kg"
  2. 数量+单位: \d+\.?\d*[^\s]*[瓶包袋盒罐桶箱]                 → "6瓶"
  3. 重量/容量: \d+\.?\d*\s*(g|kg|斤|ml|L|l|升|公斤|两)      → "300g", "1.65L"
```

提取后从名称中删除，避免污染core。**提取后立即标准化**（×→*、去1*前缀），与translate_desc的标准化保持一致：

```python
def _normalize_spec(raw: str) -> str:
    s = raw.replace('×', '*').replace('x', '*').replace('X', '*')
    s = re.sub(r'^1\*', '', s).strip()
    return s
```

**关键：规格提取必须在品牌提取之前**，否则 "300g安井鱼豆腐" 就可能被品牌先匹配。

提取优先级调整为：
```
1. 老编码后缀  2. 抄码标记  3. 规格(名称任意位置)  4. 品牌  5. 状态  6. 剩余→core
```

#### C. 加工词归一化

新函数 `has_processing_intent(remark: str) -> bool`，不硬编码结果词，只匹配"动作前缀"：

```python
# 只列动作前缀，不列完整结果（切丝/切块/切丁...写不完）
PROC_PREFIXES = ['切', '去', '单冻', '速冻', '剁', '绞', '斩', '削', '剥', '刮']
```

原理：备注里有"切X"→有加工意图，不管X是丝/块/段/丁/粒/末。同理"去X"→有去废料意图。
**不需要知道X是什么，只需要知道"有操作"**。

换成：
- `has_processing_intent(remark)` → bool（有没有加工要求）
- 具体加工结果（丝/块/丁）**不从备注解析**，而是靠子串匹配时差异字符自然暴露

```
"土豆" + 备注"切丝" vs 库里"土豆丝"
  → 子串匹配: diff="丝"
  → 备注"切丝"包含"丝" → 差异可解释
  → 品名维度通过（子串）
  → 规格维度: 新品有加工意图(切X) + 差异"丝" = 库里确实有对应规格
```

**注意**：如果新品"土豆" + "切丝"，库里只有"土豆"（没有"土豆丝"）：
- 品名精确匹配 ✓
- 规格: 新品有加工意图(remark非空+含动作前缀)，库里无对应 → 待确认

#### D. 三源规格汇总

新函数 `resolve_spec(name_meaning, desc_meaning, has_processing: bool) -> SpecResult`：

```python
@dataclass
class SpecResult:
    spec_core: Optional[str]   # 最终规格值
    has_processing: bool = False  # 备注中是否检测到加工意图
    conflict: bool = False
    conflict_detail: str = ''  # 冲突说明（如"名称500ml≠描述1.65L"）
```

规则：
1. name_spec 提取后先标准化（×→*、去1*前缀），desc_spec 已由 translate_desc 标准化
2. 两者都有且标准化后不同 → conflict=True, spec_core 取 desc_spec（描述字段更权威）
3. 两者都有且相同 → spec_core 取该值
4. 只有一方有 → 使用该值
5. 都没有 → spec_core=None
6. has_processing 独立记录（来自备注的动作前缀检测），不参与spec_core比较

### 3.2 matcher.py 新建

#### 数据结构

```python
@dataclass
class TranslatedItem:
    """新品翻译后的完整结果——check_dimensions 的 new 参数"""
    core: str
    brand: Optional[str]
    has_status: Optional[str]
    unit: str
    category: str = ''  # 新品可能无分类

@dataclass
class IndexedRow:
    """基准库中的一条索引记录"""
    spuid: str
    core: str
    brand: Optional[str]
    spec_core: Optional[str]
    has_processing: bool = False  # 基准库始终为False（无备注）
    unit: str
    raw_name: str
    category: str = ''         # 一级分类（is_status_redundant用）
    has_chaoma: bool
    has_status: Optional[str]
    hit_count: int = 0  # 销售订单命中次数，用于多候选时的推荐优先级

@dataclass
class CandidateMatch:
    """一个候选匹配的四维比对结果"""
    spuid: str
    raw_name: str
    dim_name: bool      # 品名维度是否通过
    dim_brand: bool     # 品牌维度是否通过
    dim_spec: bool      # 规格维度是否通过
    dim_unit: bool      # 单位维度是否通过
    name_detail: str    # "exact"/"synonym"/"substring"/"status_conflict"/"mismatch"
    spec_detail: str    # 规格匹配详情
    has_chaoma: bool = False  # 从IndexedRow透传，pick_best用
    hit_count: int = 0        # 从IndexedRow透传，pick_best用
    spec_core: Optional[str] = None  # 从IndexedRow透传，pick_best用

@dataclass
class MatchResult:
    """最终匹配结果"""
    result: str         # "建议复用" / "需新增" / "待确认"
    suggested_spuid: Optional[str]
    candidates: list[CandidateMatch]
    detail: str         # 人类可读的匹配说明
```

#### 核心流程

```
check_one(new_item, index) -> MatchResult:
  1. 翻译新品：
     name_meaning = translator.translate_name(名称)
     desc_meaning = translator.translate_desc(描述, 单位)
     has_proc = has_processing_intent(备注)   # 只检测有无动作前缀，不解析具体结果
  2. 汇总规格：spec_result = resolve_spec(name_meaning, desc_meaning, has_proc)
  3. 组装 TranslatedItem(core=name_meaning.core, brand=name_meaning.brand,
                         has_status=name_meaning.has_status, unit=单位)
  4. 查索引：new_item.core → 候选列表（直接匹配）
  5. 同时查异名：SYNONYM_MAP中core的异名 → 用异名core再查 → 合并候选
  6. 同时尝试子串匹配：遍历索引找core为子串/超串的条目 → 合并候选
  7. 去重候选（同一spuid可能从多条路径命中）
  8. 对每个候选，check_dimensions(translated_item, spec_result, 备注, candidate)
  9. classify(translated_item, candidates) → MatchResult
```

#### 四维比对逻辑

```python
def check_dimensions(new: TranslatedItem, new_spec: SpecResult, new_remark: str,
                     candidate: IndexedRow) -> CandidateMatch:
    """四维比对，返回候选匹配结果"""
    
    # 维度1: 品名 = core相同/异名/子串 + paren对比 + 状态兼容
    core_match = new.core == candidate.core
    name_detail = "exact" if core_match else "mismatch"
    
    # 括号内容不同 → 除非差异仅由状态词造成，否则不合并
    if core_match and new.paren_content != candidate.paren_content:
        # 检查差异是否仅由状态词解释
        diff_words = set()
        if new.paren_content:
            diff_words.add(new.paren_content)
        if candidate.paren_content:
            diff_words.add(candidate.paren_content)
        # 差异词都在状态词表中 → 差异仅状态 → 可合并
        if not all(w in STATUS_WORDS for w in diff_words):
            name_detail = "paren_conflict"
            core_match = False
    
    if not core_match:
        # 异名检查
        if new.core in SYNONYM_MAP and candidate.core in SYNONYM_MAP[new.core]:
            core_match = True
            name_detail = "synonym"
        elif candidate.core in SYNONYM_MAP and new.core in SYNONYM_MAP[candidate.core]:
            core_match = True
            name_detail = "synonym"
    
    if not core_match:
        # 子串检查：一个core是另一个的子串，且差异能被备注解释
        shorter, longer = sorted([new.core, candidate.core], key=len)
        if shorter and shorter in longer:
            diff = longer.replace(shorter, '', 1)
            if diff in (new_remark or ''):
                core_match = True
                name_detail = "substring"
    
    # 品名通过后检查状态兼容性
    status_ok = True
    if core_match:
        s1, s2 = new.has_status, candidate.has_status
        if s1 != s2:
            s1_redundant = is_status_redundant(s1, new.category) if s1 else False
            s2_redundant = is_status_redundant(s2, candidate.category) if s2 else False
            status_ok = (not s1 and s2_redundant) or (not s2 and s1_redundant)
            if not status_ok:
                name_detail = "status_conflict"  # core命中但状态不兼容
    
    name_ok = core_match and status_ok
    
    # 维度2: 品牌
    brand_ok = (not new.brand and not candidate.brand) or (new.brand == candidate.brand)
    
    # 维度3: 规格+加工
    spec_ok, spec_detail = check_spec(new_spec, candidate)
    
    # 维度4: 单位
    unit_ok = new.unit == candidate.unit
    
    return CandidateMatch(
        spuid=candidate.spuid,
        raw_name=candidate.raw_name,
        dim_name=name_ok,
        dim_brand=brand_ok,
        dim_spec=spec_ok,
        dim_unit=unit_ok,
        name_detail=name_detail,
        spec_detail=spec_detail,
        has_chaoma=candidate.has_chaoma,   # 透传，pick_best用
        hit_count=candidate.hit_count,     # 透传，pick_best用
        spec_core=candidate.spec_core,     # 透传，pick_best用
    )


def check_spec(new_spec: SpecResult, candidate: IndexedRow) -> tuple[bool, str]:
    """规格维度比对"""
    nc = new_spec
    
    # 如果新品自身规格冲突（名称和描述规格不一致），标记待确认
    if nc.conflict:
        return False, f"规格冲突({nc.conflict_detail})"
    
    # 情况1: 双方都无规格且无加工意图 → 通过（含空≈抄码≈散称）
    if not nc.spec_core and not candidate.spec_core \
       and not nc.has_processing and not candidate.has_processing:
        return True, "均无规格"
    
    # 情况2: 双方都有规格 → 比对spec_core值
    if nc.spec_core and candidate.spec_core:
        if nc.spec_core == candidate.spec_core:
            # 规格一致, 再比加工意图
            if nc.has_processing == candidate.has_processing:
                return True, "规格一致, 加工一致"
            else:
                return False, "spec_mismatch_unilateral"
        else:
            return False, f"规格不同({nc.spec_core}≠{candidate.spec_core})"
    
    # 情况3: 新品有规格、库无规格 → 信息不对等（待确认）
    if nc.spec_core and not candidate.spec_core:
        return False, "spec_mismatch_unilateral"
    
    # 情况4: 新品无规格、库有规格 → 信息不对等（待确认）
    if not nc.spec_core and candidate.spec_core:
        return False, "spec_mismatch_unilateral"
    
    # 情况5: 双方规格都无，但至少一方有加工意图 → 比加工意图
    if not nc.spec_core and not candidate.spec_core:
        if nc.has_processing == candidate.has_processing:
            return True, "均无规格, 加工意图一致"
        else:
            return False, "spec_mismatch_unilateral"
    
    return False, "spec_mismatch_unilateral"
```

#### 子串匹配

```python
def try_substring_match(new_core, new_remark, index):
    """子串匹配预过滤——扫描索引找到core为子串/超串的候选。
    实际子串验证（差异可解释）在 check_dimensions 中完成。
    此函数仅减少需要四维比对的候选数量。"""
    candidates = []
    for core in index:
        shorter, longer = sorted([new_core, core], key=len)
        # 最短一方至少2字符，避免"肉"匹配几十个无关候选
        if shorter and len(shorter) >= 2 and shorter in longer:
            # 只需要子串关系存在，差异可解释性由 check_dimensions 判定
            candidates.extend(index[core])
    return candidates
```

注意：子串匹配验证的具体逻辑在 check_dimensions 中（差异能否被备注解释），最终 name_detail 标记为 "substring"。

#### 结果分类

```python
def classify(new_item, candidates) -> MatchResult:
    # 筛选四维全过的候选
    full_match = [c for c in candidates if c.dim_name and c.dim_brand and c.dim_spec and c.dim_unit]
    
    if full_match:
        best = pick_best(full_match)
        return MatchResult("建议复用", best.spuid, candidates, 
                          detail=format_full_match_detail(best, full_match))
    
    # 子串匹配通过 + 其他三维过 → 待确认
    substring_hits = [c for c in candidates 
                      if c.name_detail == "substring" and c.dim_brand and c.dim_spec and c.dim_unit]
    if substring_hits:
        best = pick_best(substring_hits)
        return MatchResult("待确认", best.spuid, candidates,
                          detail=format_substring_detail(best))
    
    # 品名通过但规格不对等(一方有规格/加工一方没有) → 待确认
    spec_unilateral = [c for c in candidates 
                       if c.dim_name and c.dim_brand and c.dim_unit 
                       and c.spec_detail == "spec_mismatch_unilateral"]
    if spec_unilateral:
        return MatchResult("待确认", None, candidates,
                          detail=format_spec_unilateral_detail(spec_unilateral))
    
    # core命中但状态不兼容 → 需新增
    status_conflicts = [c for c in candidates if c.name_detail == "status_conflict"]
    if status_conflicts:
        return MatchResult("需新增", None, candidates,
                          detail=f"品名命中但处理状态不兼容(新品={new_item.has_status}, 库={status_conflicts[0].raw_name}状态={...})")
    
    # 品名通过但其他维明确失败(品牌不同/规格不同/单位不同) → 需新增
    name_match = [c for c in candidates if c.dim_name]
    if name_match:
        reasons = []
        for c in name_match[:3]:
            if not c.dim_brand:
                reasons.append(f"品牌不同({new_item.brand}≠{c.raw_name}的品牌)")
            if not c.dim_spec and c.spec_detail != "spec_mismatch_unilateral":
                reasons.append("规格不同")
            if not c.dim_unit:
                reasons.append(f"单位不同({new_item.unit}≠...)")
        return MatchResult("需新增", None, candidates,
                          detail="; ".join(set(reasons)) if reasons else "品名通过但其他维度不匹配")
    
    # 品名未匹配（完全没找到）
    return MatchResult("需新增", None, [],
                      detail=f"品名\"{new_item.core}\"未在库中找到匹配")

#### 最佳匹配选择

有多个四维全过的候选时，优先级：
1. 无抄码 > 有抄码（推荐干净的正常名编码）
2. hit_count 高 > 低（推荐客户最常用的编码）
3. 有规格 > 无规格（信息更完整）

```python
def pick_best(candidates):
    return max(candidates, key=lambda c: (
        not c.has_chaoma,     # 1. 无抄码优先
        c.hit_count,           # 2. 命中次数高优先
        1 if c.spec_core else 0,  # 3. 有规格优先
    ))
```

### 3.3 build_index.py 新建

```python
"""
基准库预处理 — 用新翻译器重建12440条索引
输入: 商品库整理_结果.xlsx (列1-5: spuid/名称/单位/描述/分类, 列10: 命中次数)
输出: index.json
"""
```

流程：
1. 读取 `商品库整理_结果.xlsx` Sheet(2)
2. 用新翻译器重新翻译每条：
   - translate_name(名称, 分类) → NameMeaning (含 name_spec)
   - translate_desc(描述, 单位) → DescMeaning (含 spec_core)
   - resolve_spec(name_meaning, desc_meaning, has_processing=False) → SpecResult
   - 因为基准库无备注，has_processing 始终为 False
3. 从第10列读取命中次数
4. 构建索引：`{core_name: [IndexedRow(spuid, core, brand, spec_core=spec_result.spec_core, ...), ...]}`
5. 转为 dict 后 json.dump 输出为 JSON 文件（dataclass 不能直接序列化）

> 为什么用结果表而非原始表：结果表包含全部原始数据（列1-5）和命中次数（列10），一次读取即可。

索引示例：
```json
{
  "冬枣": [
    {"spuid": "C34286990", "core": "冬枣", "brand": null, "spec_core": null, "has_processing": false, "unit": "斤", "category": "水果类", "raw_name": "冬枣", "has_chaoma": false, "has_status": null, "hit_count": 193},
    {"spuid": "C33870283", "core": "冬枣", "brand": null, "spec_core": null, "has_processing": false, "unit": "斤", "category": "水果类", "raw_name": "冬枣抄码", "has_chaoma": true, "has_status": null, "hit_count": 131}
  ],
  ...
}
```

hit_count 从 `商品库整理_结果.xlsx` 第10列（报价单命中次数）读取。多候选时优先级：无抄码 > hit_count高 > 有规格。

## 七、已知边缘场景

| 场景 | 处理方式 | 风险 |
|------|---------|------|
| 新品无分类 | `is_status_redundant` 退化为严格比对 | 可能把"鲜猪肉(无分类)"和"猪肉(鲜肉类)"判为不兼容（低概率） |
| 子串匹配误判 | 通过后标记"待确认"，不自动复用 | "鱼香肉丝" vs "鱼香肉" 会被标注待确认 |
| 异名表不对称 | SYNONYM_MAP 双向都查 | 如果只配了A→B没配B→A会有遗漏，当前MAP是双向的 |
| 加工词漏配 | 不认识的备注内容被忽略 | 新动词前缀（不在PROC_PREFIXES中的）不会被识别为加工。但可通过子串匹配间接暴露（差异字符在备注中找到即可） |
