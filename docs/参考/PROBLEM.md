# 问题陈述：二期新品增量查重

## 问题

商品库有12440条编码（一期已清洗去重）。采购或运营新增商品时，不知道新商品是否已有编码。同一种东西录了多个编码，导致订单分散、库存混乱、数据不可信。

当前是人工判断，慢且不稳定。需要自动化。

## 背景

- 一期已完成12440条商品库清洗去重，建立了语义翻译器（translator.py）和规则引擎（rules.py）
- 一期产出了品名、品牌、规格、单位四维度的翻译能力
- 一期踩坑：品牌差异（品牌修复）、括号内容差异（paren_content修复）
- 新品模板：名称、单位、描述、备注（可能无分类）
- 技术约束：Python + openpyxl，禁止外部API

## 目标

新品入库前，系统自动比对基准库（12440条），判断能否复用已有编码：
- 能复用 → 推荐已有SPUID
- 不能复用 → 确认需新建编码
- 不确定 → 标记待人工确认

## 成功标准

- [ ] 抄码名新品能匹配到库里的正常名编码（案例1）
- [ ] 多个候选时有推荐策略（案例2）
- [ ] 名称中混入的规格能被提取并参与比对（案例3）
- [ ] 括号处理状态不影响品名匹配（案例4）
- [ ] 单位不同判定为不同商品（案例5）
- [ ] 异名表能命中（案例6）
- [ ] 完全不在库的新品正确判定为需新增（案例7）
- [ ] 品牌不同判定为不同商品（案例8）
- [ ] 备注有加工要求但库无对应时标记待确认（案例9）
- [ ] 子串匹配+备注解释能发现潜在匹配（案例10）

## 不在范围内

- 一期12440条基准库的再清洗（一期已完成）
- 新品的自动创建编码（只判断能否复用）
- 销售数据分析
- Web界面或API封装（三期exe封装）
